# Chat Room

A starter direct-messaging app with PostgreSQL persistence, Socket.IO chat and in-app notifications, PostgreSQL-backed scheduled delivery and message expiry, and a React/Vite client.

## Requirements

- Node.js 20.19+ and npm
- PostgreSQL

## Setup

1. Create a PostgreSQL database named `chat_app`, then run `schema.sql` against it.
2. Update `backend/.env` with your local PostgreSQL connection string and a long random `JWT_SECRET`. The checked-in values are placeholders.
3. Install and start the backend:

   ```powershell
   cd backend
   npm install
   npm run dev
   ```

The backend adds the message read-receipt, scheduling, and expiry columns and the scheduled-message index to existing databases at startup. Scheduled delivery and expiry are handled through PostgreSQL, so Redis is not required. The backend checks for expired messages once per second. Sent messages show an eye to the sender after the recipient opens that conversation.

4. In another terminal, install and start the frontend:

   ```powershell
   cd frontend
   npm install
   npm run dev
   ```

5. Open the Vite URL (normally `http://localhost:5173`). Configure `VITE_TRANSLATE_API_URL` in `frontend/.env` to enable translation using a LibreTranslate-compatible endpoint. The app does not bundle a translation service.

### Connect from another device on your Wi-Fi

1. Find the computer running the app's local IPv4 address with `ipconfig` (for example, `192.168.1.25`).
2. Keep the frontend and backend running, then on the other device open `http://192.168.1.25:5173` in its browser. Replace the example address with the computer's actual IPv4 address. The backend accepts localhost and private-network frontend addresses on port 5173 during development, and the app connects to the API and Socket.IO server on that same computer.
3. If the device cannot connect, allow Node.js (or TCP ports 4000 and 5173) through the computer's firewall and make sure both devices are on the same Wi-Fi network. Guest Wi-Fi and client/AP isolation can block device-to-device connections.

This setup is for devices on the same local network. To connect over the internet or different networks, deploy the frontend and backend to reachable hosts and set `VITE_API_URL`, `VITE_SOCKET_URL`, and `CLIENT_ORIGIN` to their corresponding public URLs/origins. Use HTTPS for a public deployment.

Friend codes and auth tokens are generated by the backend; do not expose environment files or production secrets.

The notification bell shows incoming friend requests, accepted requests, and new messages while the user is connected. Pending friend requests are loaded when the user signs in; other notifications are kept in app memory until reload and are not stored as notification history.

Deleting a chat clears its history from the requesting user's account only; it does not delete messages from the other participant's account.

Long-press a message on touch devices or right-click it on desktop to reply, copy, forward, view message info, or delete it for yourself. You can delete your own messages for everyone.
